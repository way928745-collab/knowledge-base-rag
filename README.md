# 企业级 RAG 知识库（知识库管家）

## 这是什么

一个可直接落地的本地 RAG 知识库技能：把散落的企业资料自动分类、打标签、切片、向量化，经过一道人工审核后变成可检索的企业知识库。所有向量化和检索都在本机完成，不依赖云端 API。

## 有什么作用

- 📚 **统一知识库**：同一份文档只入库一次，用标签区分客服、员工、宣传等使用场景，不用拆成多个库。
- 🏷️ **自动分类打标**：按 8 大企业内容领域自动分类，并推断用途、受众、密级、版本等元数据。
- 🔍 **可过滤检索**：按领域、受众、密级、生效时间组合过滤，避免旧政策、内部机密被误检索出来。
- 🧾 **原文档案层**：原始文件作为唯一可信源保留，检索结果带切片引用，可回原文核对。
- 🛂 **人工审核闸门**：新资料默认进入「待审核」，批准后才进入正式检索，防止草稿和错误资料污染知识库。
- 🧹 **维护与过期清理**：检查失效、密级、版本状态，定期清理过期内容。
- 💻 **本地离线运行**：向量模型本地下载后离线可用，资料不出本机。

## 能帮助谁

企业行政/知识管理负责人、客服团队、内部员工助手搭建方，以及需要把产品资料、制度、FAQ 统一检索但不想上云或不想维护多套向量库的团队。

## 解决什么问题

| 痛点 | 本技能的机制 |
|---|---|
| 📂 资料散落各处，找不到 | 统一入库、切片、向量化，检索时按标签过滤 |
| 🏢 客服/员工/宣传要不同内容 | 一份文档打静态标签，业务按标签过滤 |
| 🚫 旧政策被误答出来 | `expire_time` 过滤过期内容 |
| 🔒 内部制度漏到对外检索 | `audience` / `security_level` 两级过滤 |
| 📝 草稿误入正式库 | 默认「待审核」闸门，人工批准后才可检索 |
| 💾 怕云端泄露业务资料 | 全部在本机向量化与检索，资料不出本机 |

## 证据（真实运行数据）

本包为 v1 首次发布，已用 3 份示例文档跑通「入库 → 待审核 → 批准 → 检索 → 维护检查」全流程：

- 入库 3 个文档，自动分类正确：产品介绍 → 产品与服务；考勤制度 → 内部管理制度；FAQ → FAQ/历史问答库。
- 检索验证通过：按领域/受众过滤能命中正确切片，内部制度不会出现在对外过滤器结果中。
- 维护检查 3 条切片全部 `active`，无缺标签。

更完整的长期运行数据（文档量、检索拦截量、过期清理量）将在首月使用后补充。

## 功能核心点

1. **统一库 + 元数据标签**：单向量库，通过 `domain / usage_type / audience / security_level / effective_time / expire_time / doc_version` 做业务隔离。
2. **双层存储**：原始文档档案层为唯一可信源，向量层只存切片、元数据与引用 ID，审核通过后才切片入库。
3. **自动分类打标**：关键词规则 + 本地向量相似度自动判断领域，推断不出的字段留空，不硬猜。
4. **人工审核闸门**：`ingest` 默认进待审核，`review approve` 批准后才可被普通检索命中。
5. **检索过滤**：CLI 支持 `--domain`、`--audience` 组合，按密级和时效做收敛。
6. **维护检查**：自动报告失效、缺标签、非 active 切片，便于定期巡检。

## 注意事项

- **首次使用先初始化**：进入技能目录后先建 Python 环境、安装依赖，再开始入库。
- 数据默认落在技能目录 `kb-data/`，原文档案和向量库都在里面；开始正式使用前先确认备份策略。
- 依赖 Python 3.11 与 uv，首次执行会下载约 90MB 的中文向量模型 `BAAI/bge-small-zh-v1.5`。
- 诚实边界：本版能做切片检索和元数据过滤，不含大模型生成答案；PDF 扫描件（纯图片）暂不支持 OCR，旧 `.doc/.ppt/.xls` 需先另存为新格式。
- 隐私边界：资料只在本机处理，但正式使用前仍建议按企业安全规范确认密级和权限。
