企业级 RAG 知识库

单向量库 + 元数据标签 + 双层存储 + 人工审核闸门 · 本地离线运行（intro v1）

🧭这个技能是什么

一个可直接落地的本地 RAG 知识库：把企业资料自动分类、打标签、切片、向量化，经过人工审核后进入正式检索。所有向量化和检索都在本机完成，不依赖云端 API，资料不出本机。

🛠有什么作用

  • 统一知识库：同一份文档只入库一次，用标签区分客服、员工、宣传等使用场景，不用拆成多个向量库
  • 自动分类打标：按 8 大企业内容领域分类，并推断用途、受众、密级、版本等元数据
  • 可过滤检索：按领域、受众、密级、生效时间组合过滤，避免旧政策、内部机密被误检索出来
  • 原文档案层：原始文件作为唯一可信源保留，检索结果带切片引用，可回原文核对
  • 人工审核闸门：新资料默认进入「待审核」，批准后才进入正式检索，防止草稿和错误资料污染知识库
  • 维护与过期清理：检查失效、密级、版本状态，定期清理过期内容

👥能帮助谁 · 解决什么问题

适合谁
  • 企业行政 / 知识管理负责人，需要把产品资料、制度、FAQ 统一检索
  • 客服团队，需要对外口径一致的检索库
  • 搭建内部员工助手、不想上云或不想维护多套向量库的团队
解决什么
  • 📂 资料散落各处找不到 → 统一入库、切片、向量化，检索时按标签过滤
  • 🏢 客服/员工/宣传要不同内容 → 一份文档打静态标签，业务按标签过滤
  • 🚫 旧政策被误答出来 → expire_time 过滤过期内容
  • 🔒 内部制度漏到对外检索 → audience / security_level 两级过滤
  • 📝 草稿误入正式库 → 默认「待审核」闸门，人工批准后才可检索

⚙️功能核心点

核心机制设计要点
统一库 + 元数据标签单向量库，通过 domain / usage_type / audience / security_level / effective_time / expire_time / doc_version 做业务隔离
双层存储原始文档档案层为唯一可信源，向量层只存切片、元数据与引用 ID，审核通过后才切片入库
自动分类打标关键词规则 + 本地向量相似度自动判断领域，推断不出的字段留空，不硬猜
